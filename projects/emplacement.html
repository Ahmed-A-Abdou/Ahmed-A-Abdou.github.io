Emplacement — Unity Package

The Project
A Unity package containing the parts of a C-RAM air defence simulation that proved reusable. Eight runtime files in a single assembly with zero dependencies, distributed via UPM and installable from a git URL. Extracted rather than designed up front — every type in it had already been consumed by at least three unrelated systems in the source project before being pulled out.
Packaging
Structured as a UPM package: package.json at repository root, an assembly definition under Runtime/, and hand-written .meta files so asset GUIDs stay stable across updates rather than being regenerated per install.

.meta format was verified by diffing against Unity's own output for the same asset types. Unity 6 writes script metas in a short form — fileFormatVersion and guid only, no MonoImporter block, no trailing newline — and pads userData: with a trailing space. An initial hand-written set used the older explicit form; Unity silently rewrote all thirteen files on import, which would have shown every meta as modified in the first commit after install. Corrected to match byte-for-byte and confirmed untouched on re-import.
StateMachine<T>
Pure C# with no UnityEngine reference — drivable from a MonoBehaviour's Update, from a single manager ticking many instances, or from a test with no scene. That last property is what makes the scaling path from a component-per-actor to one manager and a list a change of caller rather than a rewrite.

Constrained as where T : class, IState, two constraints for two distinct reasons:
  • The type parameter is an abstract base per machine, not IState directly. A machine holding IState lets one FSM's state be passed to another and fails at runtime, far from the cause. This makes it a compile error, and lets CurrentState expose whatever the base carries with no downcasting.
  • The class constraint keeps state identity reference-based. With value types, the same-state guard would compare contents rather than instances, treating two distinct states holding equal data as one.
TransitionTo owns the whole sequence — null guard, same-state guard, Exit, assign, Enter — so callers may command every frame without re-entering a state they already occupy.

Deliberately does not poll states for a next state. That design makes a machine self-driving only, and an external command survives exactly one frame. Transition policy belongs to the caller, which is what lets one machine type serve both an autonomous actor and an externally commanded one with no mode flag.
ObjectPool<T>
Constrained to Component rather than MonoBehaviour — the loosest constraint providing gameObject, so pools of AudioSource, ParticleSystem or Collider remain possible. In the source project the same class pools drones, projectiles, audio sources and VFX instances.

Queue-backed rather than stack-backed: FIFO gives a returned instance maximum time before reuse, so a destroyed object does not visibly reappear on the next frame.

Never grows. On exhaustion it logs and returns null, because a pool that quietly expands is an allocator with extra steps and hides the sizing bug rather than reporting it. Null is returned rather than thrown so the caller can decide what it means — dropping a cosmetic effect is correct, while an unavailable simulation object is a failure.

Double-returns are guarded using the instance's own activeSelf, the only signal available at the Component level.
TransformReference / TransformProvider
A ScriptableObject holding a live scene Transform, solving the constraint that a prefab cannot reference a scene object. Both sides hold the asset instead: a provider in the scene publishes its own transform on Awake, and any prefab reads the live value back. Alternatives — a singleton, FindObjectOfType, or post-spawn wiring — all couple objects that had no reason to know about each other.

The held value is deliberately not [SerializeField]. In the Unity editor, writing to a serialised ScriptableObject field at runtime persists to disk, so the asset mutates as a side effect of entering play mode and that change reaches the next commit.

Null assignment is ignored, so a scene unloading cannot blank a reference another scene is still using.
Contracts
ITargetable (position, velocity, liveness), ISpawnable (one method), IHittable (one method). Kept separate because they have different consumers: a spawner writes, a targeting system reads, a projectile strikes, and none should be handed another's surface.

ITargetable exposes velocity rather than requiring consumers to derive it from position deltas, so one vector serves speed comparison, heading tests and lead calculation with no per-target history. IsAlive exists rather than a null check because pooled objects are deactivated, never destroyed — Unity's fake-null does not fire for them.
Verification
Validated outside the editor as well as inside it:
  • Compiled against Unity 6000.3.9f1's UnityEngine.dll and UnityEngine.CoreModule.dll targeting netstandard2.1 — 0 errors, 0 warnings
  • StateMachine<T> executed as plain .NET, since it has no engine dependency, covering the null guard, the same-state guard, Exit-before-Enter ordering, and reference-versus-value identity
  • 29 in-editor assertions across all three systems, including pool exhaustion, double-return rejection, FIFO reuse order, and confirmation via SerializedObject that the transform reference exposes no serialised field
  • .meta files confirmed unmodified after a full Unity import cycle
Scope
Two components from the source project were deliberately excluded. The global event bus, because a single static bus means every listener hears every source and cross-talks as soon as there are two of anything — a known weakness, not something to distribute. And the generic spawner, because it still depends on a project-specific config type and is therefore not yet project-agnostic.

The rule the package is built on: something is not known to be reusable until it has been reused.
Used In
The Tunable Solar System I built for my NASA Space Apps session is a second, unrelated project, and it uses four pieces of the package unchanged:
  • StateMachine<T>: the camera's Overview and Follow modes, typed on a CameraState base so only camera states fit
  • ObjectPool<T>: a fixed set of comets, reused instead of created and destroyed
  • ISpawnable: the spawner places anything that can be placed, without knowing it's a comet
  • TransformReference: the comet prefab finds the Sun through an asset, since a prefab can't link to a scene object
It's a small teaching demo, so it shows the pieces travel to a new project; MilSim is where they carry weight.
